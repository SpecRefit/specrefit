# SpecRefit 0.2.0

SpecRefit 0.2.0 improves everyday work with larger, multi-file OpenAPI contracts. It builds on the inspection, transformation and reviewed export workflow introduced in 0.1.0.

## What's improved

- **Automatic local references on desktop.** Open an entry contract and SpecRefit discovers relative reference files recursively inside its directory tree. Missing or inaccessible references produce diagnostics; all discovered source files remain protected from export writes. Files outside the selected tree and remote URLs are not fetched automatically. Browser users can still select a folder or supply missing files explicitly. ([#32](https://github.com/SpecRefit/specrefit/pull/32))
- **One contract-wide media preference.** Choose one or more request/response media types actually offered by the specification, including JSON, XML, text and multipart. Single-type content is preserved. With multiple types, selected matches are retained; when none match, the original types are kept. All types start selected, including multipart, so capabilities are removed only through an explicit choice. ([#34](https://github.com/SpecRefit/specrefit/pull/34))
- **Better small-window navigation.** Compact operation/filter navigation and independently scrolling details keep the workspace usable when resizing browser or desktop windows. The version header stays compact. ([#15](https://github.com/SpecRefit/specrefit/pull/15))
- **Clear playground build identity.** The hosted playground shows the published release version at its release commit, or a development banner with the release baseline, commit count and linked commit hash for newer builds. Stable release publication automatically rebuilds the current main playground behind the complete Build gate. ([#35](https://github.com/SpecRefit/specrefit/pull/35))
- **Fresh playground visits without a hard refresh.** A small same-origin startup check refreshes stale HTML before starting the editor; app, worker, stylesheet and logo files use content-based names. Failed checks show a retry instead of silently starting stale code. Open editing sessions are not automatically reloaded, and desktop/local startup stays offline. During the initial rollout, pages cached before this mechanism existed may still need one final hard refresh or cache expiry. ([#36](https://github.com/SpecRefit/specrefit/pull/36))

Contract processing remains local, without accounts, telemetry or a processing server. The hosted startup check retrieves only application build identity and sends no contract data.

## Downloads and upgrading

Download the archive matching your platform, extract it into a new folder and launch `SpecRefit.exe` on Windows, `SpecRefit.app` on macOS or `SpecRefit` on Linux. Export any work you need before closing an existing session. No separate Node.js or Electron installation is required; Linux needs a graphical session and Chromium system libraries. The browser archive contains static files for hosting, not a desktop executable.

The release provides Windows x64, macOS Apple Silicon and Intel, Linux x64 and browser archives, plus `manifest.json` and `SHA256SUMS` for build identity and integrity verification. GitHub's automatically generated source archives are not runtime-inclusive applications.

Windows packages remain unsigned. macOS packages have ad-hoc signatures without Developer ID or notarization, so downloaded apps may be blocked by OS security policy. Native CI tests startup, shared-engine behavior and export from extracted packages without Node on PATH; full clean-machine and browser-download quarantine acceptance remain open. Native installers are not included.

## Scope

Representative OpenAPI 3.0.4, 3.1.2 and 3.2.0 fixtures are tested. SpecRefit is not a complete OpenAPI or JSON Schema validator. Broader reference/dialect semantics, saved project configuration, contract comparison, CLI and Maven integration remain planned. This 0.x release does not imply completion of the roadmap or a compatibility guarantee for future versions.
